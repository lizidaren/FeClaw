# =============================================================================
# FeClaw 依赖声明层（人类可读的版本范围）
#
# 与 requirements.lock 的关系（两者不冲突，职责不同）：
#   * 本文件 = 声明层：直接依赖 + 允许的版本范围（`>=`）；可读、可评审、可升级。
#   * requirements.lock = 锁定层：**已验证可跑**的精确版本（`==`），按分组标注
#     core / optional / fuse / test / transitive；可重现安装用它。
#
# 因此：
#   * 可重现安装（唯一权威）：pip install -r requirements.lock
#   * 只想装核心（不含 FUSE/可选功能）：取 requirements.lock 的 `core` 分组
#   * FUSE 挂载：额外装 requirements-fuse.txt（trio + pyfuse3），lock 里是 `fuse` 分组
#   * 测试：requirements-dev.txt（lock 里是 `test` 分组）
#
# 改本文件后 lock 不会自动更新：按 requirements.lock 头部「如何重新生成」那一节
# 复现一次，并把新版本在干净 venv 里跑过测试再提交（不要凭空 pin 未验证的版本）。
#
# 分组依据（2026-10-25 基线 e2adb08，Python 3.12.9 venv 实测）：
#   对 345 个 .py 文件做 AST 扫描，凡在 app 树（main/config/models/routers/
#   services/utils）里**模块级、未 guard** import 的第三方模块 → core；
#   只在函数体内或 try/except ImportError 内 import 的 → optional（缺失时该功能
#   不可用，而不是整个应用起不来）。
# =============================================================================
